# Decisions

Changes from, or clarifications of, `catalogue-store-prompt.md`. Newest first.

## 2026-10-26 — Phase 1

| #   | Decision                                                                                                                         | Why                                                                                                                                                                                                                                                          |
| --- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | **No Docker.** MongoDB is provided via `MONGODB_URI` (Atlas).                                                                    | The owner already has a URI. Atlas, including the free M0 tier, is always a replica set, so transactions work. For a local DB, run `mongod --replSet rs0` and `rs.initiate()` once. The API logs a warning at startup if it connects to a standalone server. |
| 2   | **Express stays, but behind a Next.js rewrite** (`/api/v1/*` → `API_INTERNAL_URL`).                                              | The browser only sees one origin. Auth cookies stay first-party (no Safari/ITP cross-site cookie problems between Vercel and Render), and CORS, `COOKIE_DOMAIN` and CSRF tokens become unnecessary.                                                          |
| 3   | **No CSRF token library.** Instead: `sameSite=lax` httpOnly cookie + `Origin` header check on mutating admin requests (Phase 2). | Same-origin plus SameSite already blocks cross-site form posts. The Origin check is defence in depth.                                                                                                                                                        |
| 4   | **Single session JWT cookie, no refresh tokens.**                                                                                | Only one user ever logs in. A 7–14 day cookie with re-login on expiry is simpler and just as safe.                                                                                                                                                           |
| 5   | **Stock is decremented when the order is placed** (inside the order-creation transaction) and restored on cancel.                | The prompt was contradictory (§3.2 "on confirm" vs §5 "atomic decrement in creation transaction"). Reserving at placement is the only option that prevents overselling. `Order.stockRestoredAt` makes restoring idempotent.                                  |
| 6   | **No `visitorsessions` collection; the Live page short-polls (every 10s)** an aggregation over `analyticsevents`.                | The last 5 minutes of events already contain everything needed. Polling is simpler than SSE and works through the Next.js proxy, Vercel and any load balancer without extra tuning.                                                                          |
| 7   | **No coarse city / GeoIP.**                                                                                                      | Needs a GeoIP database for little value. Referrer and device type are stored; IPs never are.                                                                                                                                                                 |
| 8   | **Bulk import uses `bulkWrite({ ordered: false })` with a per-row report**, not a transaction.                                   | Partial success with a clear error report is more useful to the owner than all-or-nothing.                                                                                                                                                                   |
| 9   | **No Husky / lint-staged.**                                                                                                      | Little benefit for a single developer. `pnpm lint && pnpm typecheck && pnpm test` is the gate.                                                                                                                                                               |
| 10  | **Customer totals are aggregated from orders**, not stored on the customer.                                                      | Avoids denormalised counters drifting when orders are cancelled or edited.                                                                                                                                                                                   |
| 11  | **`images[0]` is the product cover image.**                                                                                      | Drag-to-reorder then sets the cover implicitly. No separate field to keep in sync.                                                                                                                                                                           |
| 12  | **Order numbers restart every year** (`ORD-2026-00001`), using a counter per year (`counters._id = "order-2026"`).               | Matches the requested format, and the atomic `$inc` + upsert never counts documents.                                                                                                                                                                         |
| 13  | **Indexes:** `autoIndex` is on in development. In production `pnpm seed` runs `syncIndexes()`.                                   | Avoids index builds on every production boot. Seed is idempotent and meant to run on every deploy.                                                                                                                                                           |
| 14  | **`@catafy/types` is compiled to `dist/`** (turbo builds it before dependents).                                                  | Both Node (Express) and Next.js consume plain ESM JS with declarations, so neither needs a special TS loader for workspace packages.                                                                                                                         |
