# Decisions

Changes from, or clarifications of, `catalogue-store-prompt.md`. Newest first.

## 2026-10-28 — Phase 4

| #   | Decision                                                                                                                                                                                                                                                                                 | Why                                                                                                       |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 34  | **Order creation = one MongoDB transaction:** re-quote from DB → conditional `$inc` per line (`variants.$elemMatch: { stock: { $gte: qty } }`) → upsert customer → next order number → insert order. Any failure rolls everything back, including the counter.                           | Tested: 5 concurrent buyers for the last piece → exactly one 201, stock 0, order numbers stay contiguous. |
| 35  | **Prices always come from the database.** The bag in `localStorage` stores prices only as a display hint; `POST /public/cart/quote` re-prices and flags `unavailable` / `out_of_stock` / `insufficient_stock` / `below_moq`, and checkout re-runs the same quote inside the transaction. | Never trust client prices (spec §5). A single function serves the cart page and order creation.           |
| 36  | **The confirmation page is `/order/<token>`** (24-char random token), not the order number, and the API sends `Cache-Control: no-store`.                                                                                                                                                 | Order numbers are sequential and guessable; the page shows the buyer's address and phone.                 |
| 37  | **Placing an order revalidates the storefront cache.**                                                                                                                                                                                                                                   | Stock changed. Found in E2E testing: without this, a sold-out item showed as available for up to an hour. |
| 38  | **MOQ applies per product across all its variants; for pack products, quantity and stock count sets** and the price is per set.                                                                                                                                                          | Matches how wholesale and pack ordering works. Simplest consistent rule.                                  |
| 39  | **No shipping or tax lines in v1:** total = subtotal. The cart says "delivery & payment confirmed on WhatsApp".                                                                                                                                                                          | No payment gateway and no shipping engine were requested; the owner confirms charges manually.            |
| 40  | **Buyer details are remembered in `localStorage` on that device only.**                                                                                                                                                                                                                  | Repeat buyers on phones don't retype their address; nothing extra is stored server-side.                  |
| 41  | **The WhatsApp order message is built in `apps/web/lib/order-message.ts`.**                                                                                                                                                                                                              | The settings template (Phase 7) will plug in there.                                                       |
| 42  | **`NEXT_DIST_DIR` env var** (default `.next`).                                                                                                                                                                                                                                           | Allows a production build/test to run alongside `next dev`.                                               |

## 2026-10-28 — Phase 3

| #   | Decision                                                                                                                                                                                                                       | Why                                                                                                                                                               |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 25  | **One cache tag (`catalog`) for all storefront data**, revalidated by the API after every successful admin write (`POST /api/revalidate`, shared secret, timing-safe compare). Hourly time-based revalidation is the fallback. | A boutique catalogue is small. Per-product tags would add bookkeeping for no visible gain. Verified: price edits and deletes show on the next request.            |
| 26  | **Storefront pages render per request (`connection()`) but read API data from the Next.js data cache.** No full-page ISR.                                                                                                      | `next build` never needs the API running (CI and Vercel builds stay simple). Rendering cached data is fast, and buyers never see stale data after an edit.        |
| 27  | **Dropped the MongoDB text index; search is a case-insensitive substring match** on title and tags.                                                                                                                            | `$text` matches whole words only ("kurt" ≠ "Kurti"), which is the wrong behaviour for shoppers typing on phones. Substring search is fine at this catalogue size. |
| 28  | **Server Components call the API directly** (`API_INTERNAL_URL`); browsers still go through the `/api/v1` rewrite.                                                                                                             | Avoids a pointless hop through Next's own proxy on the server.                                                                                                    |
| 29  | **Open Graph images go through the Next.js image optimizer** (`/_next/image?w=1200`), and the price is in `og:title`.                                                                                                          | WhatsApp previews show the image, title and price, and load a resized image instead of the R2 original.                                                           |
| 30  | **Only categories and catalogues with at least one visible product appear in the storefront.**                                                                                                                                 | No empty tiles or dead links.                                                                                                                                     |
| 31  | **Private catalogues return 404 for now.** Visibility lives in one place (`VISIBLE_PRODUCT` in `storefront.service.ts`) so Phase 6 can add the passcode rule there.                                                            | The spec requires private products never leak, so there's a single choke point.                                                                                   |
| 32  | **Product page offers "Ask on WhatsApp" until the cart arrives (Phase 4).**                                                                                                                                                    | The page is useful as soon as it's shared.                                                                                                                        |
| 33  | **`OWNER_EMAIL`/`OWNER_PASSWORD` are validated only by the seed script.**                                                                                                                                                      | A short seed password was stopping the whole API from starting. The seed still requires 10+ characters.                                                           |

## 2026-10-28 — Phase 2

| #   | Decision                                                                                                                                                                                                                         | Why                                                                                                                                           |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 15  | **Session = HS256 JWT (jose) in an httpOnly `sameSite=lax` cookie, 14 days.** Next.js middleware (Node runtime) verifies it with the same `JWT_SECRET` to redirect before rendering; the API re-verifies on every admin request. | The middleware is only a UX gate. Authority stays in the API.                                                                                 |
| 16  | **CSRF = `Origin` (or `Referer`) must equal `WEB_ORIGIN` on every mutating `/admin` request**, including login.                                                                                                                  | Browsers always send Origin on cross-site POST/PUT/DELETE. Requests with neither header are rejected.                                         |
| 17  | **Image width/height are read in the browser** (`createImageBitmap`) before upload and saved with the key.                                                                                                                       | The API never touches image bytes. Dimensions are only used for layout, so trusting the owner's browser is fine.                              |
| 18  | **Presigned PUTs sign `Content-Type`, `Content-Length` and `Cache-Control`** and expire in 5 minutes. Keys are `<folder>/<uuid>.<ext>`, and the API rejects image keys that don't match that pattern on save.                    | Verified against R2: a different size or type gets a 403. SVG is not allowed (it can carry scripts).                                          |
| 19  | **Removed or replaced product images are not deleted from R2.**                                                                                                                                                                  | Past orders snapshot `imageKey`. Deleting would break order history. Storage is cheap; a cleanup script for unreferenced keys can come later. |
| 20  | **Variant ids are preserved on product update**; an id that doesn't belong to the product is rejected.                                                                                                                           | Orders (Phase 4) and carts reference `variantId`.                                                                                             |
| 21  | **Product soft delete also renames the slug** (`<slug>--deleted-<id6>`) and clears SKUs.                                                                                                                                         | The unique indexes would otherwise block re-creating a product with the same slug or SKU.                                                     |
| 22  | **Categories with products can't be deleted** (409).                                                                                                                                                                             | Avoids orphaned `categoryId`s. The owner moves products first.                                                                                |
| 23  | **Every product needs at least one variant** (the default is "Free size / Default").                                                                                                                                             | Stock and ordering always work per variant, so there is one code path.                                                                        |
| 24  | **Admin product search uses a case-insensitive regex** (title, tags, SKU). The text index is for the storefront.                                                                                                                 | Partial words like "chik" work, which is what the owner expects.                                                                              |

## 2026-10-26 — Phase 1

| #   | Decision                                                                                                                         | Why                                                                                                                                                                                                                                                          |
| --- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | **No Docker.** MongoDB is provided via `MONGODB_URI` (Atlas).                                                                    | The owner already has a URI. Atlas, including the free M0 tier, is always a replica set, so transactions work. For a local DB, run `mongod --replSet rs0` and `rs.initiate()` once. The API logs a warning at startup if it connects to a standalone server. |
| 2   | **Express stays, but behind a Next.js rewrite** (`/api/v1/*` → `API_INTERNAL_URL`).                                              | The browser only sees one origin. Auth cookies stay first-party (no Safari/ITP cross-site cookie problems between Vercel and Render), and CORS, `COOKIE_DOMAIN` and CSRF tokens become unnecessary.                                                          |
| 3   | **No CSRF token library.** Instead: `sameSite=lax` httpOnly cookie + `Origin` header check on mutating admin requests (Phase 2). | Same-origin plus SameSite already blocks cross-site form posts. The Origin check is defence in depth.                                                                                                                                                        |
| 4   | **Single session JWT cookie, no refresh tokens.**                                                                                | Only one user ever logs in. A 7–14 day cookie with re-login on expiry is simpler and just as safe.                                                                                                                                                           |
| 5   | **Stock is decremented when the order is placed** (inside the order-creation transaction) and restored on cancel.                | The prompt was contradictory (§3.2 "on confirm" vs §5 "atomic decrement in creation transaction"). Reserving at placement is the only option that prevents overselling. `Order.stockRestoredAt` makes restoring idempotent.                                  |
| 6   | **No `visitorsessions` collection; the Live page short-polls (every 10s)** an aggregation over `analyticsevents`.                | The last 5 minutes of events already contain everything needed. Polling is simpler than SSE and works through the Next.js proxy, Vercel and any load balancer without extra tuning.                                                                          |
| 7   | **No coarse city / GeoIP.**                                                                                                      | Needs a GeoIP database for little value. Referrer and device type are stored; IPs never are.                                                                                                                                                                 |
| 8   | **Bulk import uses `bulkWrite({ ordered: false })` with a per-row report**, not a transaction.                                   | Partial success with a clear error report is more useful to the owner than all-or-nothing.                                                                                                                                                                   |
| 9   | **No Husky / lint-staged.**                                                                                                      | Little benefit for a single developer. `pnpm lint && pnpm typecheck && pnpm test` is the gate.                                                                                                                                                               |
| 10  | **Customer totals are aggregated from orders**, not stored on the customer.                                                      | Avoids denormalised counters drifting when orders are cancelled or edited.                                                                                                                                                                                   |
| 11  | **`images[0]` is the product cover image.**                                                                                      | Drag-to-reorder then sets the cover implicitly. No separate field to keep in sync.                                                                                                                                                                           |
| 12  | **Order numbers restart every year** (`ORD-2026-00001`), using a counter per year (`counters._id = "order-2026"`).               | Matches the requested format, and the atomic `$inc` + upsert never counts documents.                                                                                                                                                                         |
| 13  | **Indexes:** `autoIndex` is on in development. In production `pnpm seed` runs `syncIndexes()`.                                   | Avoids index builds on every production boot. Seed is idempotent and meant to run on every deploy.                                                                                                                                                           |
| 14  | **`@catafy/types` is compiled to `dist/`** (turbo builds it before dependents).                                                  | Both Node (Express) and Next.js consume plain ESM JS with declarations, so neither needs a special TS loader for workspace packages.                                                                                                                         |
